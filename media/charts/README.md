# Chart set: NPU showcase results

Generated by `scripts/make_charts.py` from `benchmarks/results/*.json`. Do not edit by hand: re-run
`.venv\Scripts\python.exe scripts/make_charts.py` (or `--only <name>`) after re-recording results.

Hardware: Intel Core Ultra 5 322 (Panther Lake); NPU 5 "Intel AI Boost", 46 TOPS INT8; Intel Graphics, 2 Xe3 cores; CPU 2P + 4LP-E, 6 threads. NPU driver 32.0.100.5540, graphics driver 32.0.101.9175, OpenVINO 2026.4.1. Clean run 2026-11-12: idle machine, on AC, devices run one at a time.

All PNGs are 1920 x 1080. File names are a contract with the decks and the site; do not rename them.

## Technical set

### `latency_by_workload.png`

**Takeaway:** The NPU has the lowest median latency on 5 of 6 workloads (log scale; p50 bars, p95 whiskers; lower is better).

**Data:** `benchmarks/results/depth_parallax.json`, `benchmarks/results/llm_chat.json`, `benchmarks/results/perf_atlas.json`, `benchmarks/results/vision_side_by_side.json`

**Numbers:**

- Vision detect, YOLOX-tiny 416, INT8 (vision_side_by_side.json): NPU p50 2.29 ms / p95 2.47 ms; GPU p50 4.23 ms / p95 4.35 ms; CPU p50 11.88 ms / p95 13.10 ms -> fastest NPU
- Segmentation, selfie seg 256 (vision_side_by_side.json): NPU p50 0.84 ms / p95 0.94 ms; GPU p50 1.08 ms / p95 1.21 ms; CPU p50 2.62 ms / p95 2.95 ms -> fastest NPU
- Depth, Depth-Anything-V2-S 364 (depth_parallax.json): NPU p50 12.52 ms / p95 20.14 ms; GPU p50 17.28 ms / p95 17.43 ms; CPU p50 133.90 ms / p95 138.73 ms -> fastest NPU
- Atlas CONV-M, batch 32, FP16 (perf_atlas.json): NPU p50 5.25 ms / p95 7.54 ms; GPU p50 7.96 ms / p95 8.21 ms; CPU p50 139.77 ms / p95 141.75 ms -> fastest NPU
- Atlas MLP-L, batch 1, FP16 (perf_atlas.json): NPU p50 3.46 ms / p95 4.27 ms; GPU p50 3.48 ms / p95 3.86 ms; CPU p50 5.04 ms / p95 5.42 ms -> fastest NPU
- LLM per-token, Phi-3-mini INT4 (llm_chat.json): NPU p50 46.90 ms / p95 47.90 ms; GPU p50 45.55 ms / p95 46.80 ms; CPU p50 52.90 ms / p95 60.90 ms -> fastest GPU

**Notes:**

- LLM per-token = pooled inter-token intervals over the 4 prompts (TTFT excluded).
- Vision/segmentation timings exclude decode, pre/post-processing and drawing.

### `llm_compare.png`

**Takeaway:** The NPU generates nearly as fast as the GPU (21.6 vs 21.8 tok/s) with 7× less CPU; the GPU answers first.

**Data:** `benchmarks/results/llm_chat.json`

**Numbers:**

- NPU: 21.62 tok/s, TTFT 697.5 ms, CPU cores busy 0.14 of 6, first load 29.15 s (labelled 'cold'), cached load 2.6 s
- GPU: 21.81 tok/s, TTFT 102.9 ms, CPU cores busy 1.02 of 6, first load 5.56 s (labelled 'cold'), cached load 1.75 s
- CPU: 19.07 tok/s, TTFT 476.2 ms, CPU cores busy 1.96 of 6, first load 1.29 s (labelled 'no-cache'), cached load n/a

**Notes:**

- Medians over 4 prompts, greedy decoding, max 160 new tokens, devices run one at a time.
- NPU first load (30.22 s) is recorded as cache='cached' but is really a cold compile: depth_parallax wrote a blob to the shared models/npucache just before, so the 'blobs present' check misfired.

### `cpu_cost.png`

**Takeaway:** NPU frees the CPU: 4 ms of CPU time per AI frame, vs 51 ms with the AI on the CPU.

**Data:** `benchmarks/results/offload_dashboard.json`, `benchmarks/results/llm_chat.json`

**Numbers:**

- Offload (placements format) AI-process CPU ms per AI frame: NPU 4.42 (rounds 4.42, 4.41), GPU 8.03 (rounds 7.34, 8.71), CPU 51.16 (rounds 50.37, 51.96)
- Background work kept, % of AI-off baseline: NPU 96.0 (rounds 95.8, 96.3), GPU 93.2 (rounds 96.3, 90.0), CPU 85.5 (rounds 85.3, 85.7)
- AI FPS achieved (target 30): NPU 29.96, GPU 28.93, CPU 15.16
- Offload baseline: mean_ops_s=944.7, reference_ops_s=944.7, drift_pct=-6.5, drift_first_to_last_pct=-6.5, spread_pct=15.4, method=each AI phase vs mean of the AI-off phases immediately before and after it
- LLM CPU cores busy (median of 4 prompts, of 6): NPU 0.14, GPU 1.02, CPU 1.96

**Notes:**

- CPU ms per AI frame = CPU time of the AI process / AI frames processed; it includes pre/post-processing, which runs on the CPU in every placement, so it is comparable even when AI FPS differs.
- offload_dashboard.json is being redesigned; re-run scripts/make_charts.py after the final recording.

### `compile_cost.png`

**Takeaway:** The NPU's first compile is the slowest (29 s for the LLM); the compile cache cuts it to 2.6 s.

**Data:** `benchmarks/results/llm_chat.json`, `benchmarks/results/depth_parallax.json`, `benchmarks/results/vision_side_by_side.json`

**Numbers:**

- LLM: Phi-3-mini INT4 (3.8B): NPU first 29.15 s, cached 2.6 s; GPU first 5.56 s, cached 1.75 s; CPU first 1.29 s, cached n/a
- Depth: Depth-Anything-V2-S 364: NPU first n/a, cached 1.747 s; GPU first n/a, cached 2.476 s; CPU first 4.61 s, cached n/a
- Vision: YOLOX-tiny + selfie seg: NPU first 2.328 s, cached n/a; GPU first 6.086 s, cached n/a; CPU first 0.578 s, cached n/a

**Notes:**

- Vision = detect + segment compile_s summed; that example uses no compile cache, so every start pays it.
- Depth cached load was not recorded in the clean run (cache was cold).
- LLM NPU first load is labelled 'cached' in the JSON but is a cold compile (see llm_compare).

### `npu_batch_bug.png`

**Takeaway:** NPU batching bug: conv stacks at batch 8 return wrong results, and MLP-L at batch 8 takes 24.2 ms vs 3.9 ms at batch 32 (still present on NPU driver 32.0.100.5540).

**Data:** `benchmarks/results/perf_atlas.json`

**Numbers:**

- NPU FP16 conv relative error vs numpy (tolerance 0.015): CONV-XS b1 0.000192 (executed); CONV-XS b8 0.053642 (failed_correctness); CONV-XS b32 0.000408 (executed); CONV-S b1 0.000293 (executed); CONV-S b8 0.039299 (failed_correctness); CONV-S b32 0.000331 (executed); CONV-M b1 0.000361 (executed); CONV-M b8 0.023141 (failed_correctness); CONV-M b32 0.000448 (executed)
- NPU failed_correctness configs in the whole grid: 9 (CONV-XS b8 FP32, CONV-XS b8 FP16, CONV-XS b8 INT8, CONV-S b8 FP32, CONV-S b8 FP16, CONV-S b8 INT8, CONV-M b8 FP32, CONV-M b8 FP16, CONV-M b8 INT8)
- NPU FP16 MLP p50 ms: MLP-S b1 0.5582; MLP-S b8 2.3808; MLP-S b32 0.5814; MLP-M b1 1.4912; MLP-M b8 8.1121; MLP-M b32 1.5555; MLP-L b1 3.4563; MLP-L b8 24.1880; MLP-L b32 3.8772

**Notes:**

- The atlas grid tests batch 1, 8 and 32 only. The wider 'batch 2-8 fail, batch 1 and >=12 correct' finding is documented in docs/DRIVER_SETUP.md / examples/perf_atlas/README.md, not in this JSON.
- The same 9 configs (3 conv sizes x FP32/FP16/INT8 at batch 8) fail with identical errors on the preliminary driver 32.0.100.4724.

### `driver_contention.png`

**Takeaway:** Measurement conditions matter: CPU and GPU timings moved up to 3.3× between runs; NPU timings barely moved. Drivers AND machine load both changed, so the difference cannot be attributed to the driver alone.

**Data:** `benchmarks/results/perf_atlas.json`, `benchmarks/results/llm_chat.json`, `benchmarks/results/archive/20261111_npu32.0.100.4724_preliminary/{perf_atlas,llm_chat,hardware}.json`

**Numbers:**

- CPU CONV-M b32 FP16 p50: preliminary 415.1942 ms -> clean 139.7714 ms (2.97x)
- CPU MLP-L b32 FP16 p50: preliminary 52.5832 ms -> clean 15.7875 ms (3.33x)
- GPU CONV-S b32 FP16 p50: preliminary 4.6776 ms -> clean 2.2700 ms (2.06x)
- GPU MLP-L b1 FP16 p50: preliminary 6.2248 ms -> clean 3.4806 ms (1.79x)
- NPU CONV-M b32 FP16 p50: preliminary 5.2791 ms -> clean 5.2460 ms (1.01x)
- NPU MLP-L b1 FP16 p50: preliminary 3.4388 ms -> clean 3.4563 ms (0.99x)
- GPU LLM cold load: preliminary 227.55 s -> clean 5.56 s (40.9x)

**Notes:**

- Preliminary: NPU driver 32.0.100.4724, graphics driver 32.0.101.8860, other jobs running (2026-11-11). Clean: NPU 32.0.100.5540, graphics 32.0.101.9175, idle, sequential (2026-11-12).
- LLM GPU cold load also depends on compile-cache state; both runs were labelled 'cold'.

## Simple set (advisory board)

### `simple_speed.png`

**Takeaway:** The AI chip handles 319 video frames a second: 4.6× the main processor.

**Data:** `benchmarks/results/vision_side_by_side.json`

**Numbers:**

- Vision frame p50 (detect + segment): NPU 3.1337 ms = 319.1 frames/s, GPU 5.3284 ms = 187.7 frames/s, CPU 14.4815 ms = 69.1 frames/s
- NPU vs CPU: 4.62x; NPU vs GPU: 1.70x

**Notes:**

- Frames/s = 1000 / median frame AI time; it counts only the AI step (no video decoding or drawing).

### `simple_cpu_free.png`

**Takeaway:** With live video AI on the NPU, your other work keeps 96% of its speed (86% on the main processor).

**Data:** `benchmarks/results/offload_dashboard.json`

**Numbers:**

- Background work kept, % of AI-off speed: NPU 96.0% (rounds 95.8, 96.3), GPU 93.2% (rounds 96.3, 90.0), CPU 85.5% (rounds 85.3, 85.7)
- CPU ms per AI frame: NPU 4.42, GPU 8.03, CPU 51.16

**Notes:**

- Work kept = foreground worker throughput with AI running / adjacent AI-off baseline.

### `simple_llm.png`

**Takeaway:** No internet, no cloud: the laptop's own chips write up to about 16 words a second.

**Data:** `benchmarks/results/llm_chat.json`

**Numbers:**

- Words/s = tok/s median x 0.75 (approximation): NPU 21.62 tok/s ~ 16.2 words/s, GPU 21.81 tok/s ~ 16.4 words/s, CPU 19.07 tok/s ~ 14.3 words/s

**Notes:**

- 0.75 words per token is a rule-of-thumb approximation for English text, not measured here.
